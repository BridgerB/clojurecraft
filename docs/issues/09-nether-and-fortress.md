# Enter the Nether and reach a fortress: a dimension-aware world, respawn as a reducer event, per-dimension memory, enclosed fortress search

## Summary

Today the world value is overworld-only: `chunk.clj:10-11` hard-codes `min-y -64` / `section-count 24`, `decode` (`chunk.clj:35-39`) always reads 24 sections, `:world/chunks` is keyed `[cx cz]` and `:world/sightings` `[x y z]` with no dimension (`game.clj:47-50`, `memory.clj:4`), and the `login` spec reads only `entity-id` (`packet.clj:43`), so the bot cannot tell which dimension it is in. This issue adds `:world/dimension`, a generated `dimensions.edn` table, specs for `respawn` / `registry-data` / `game-event` / `set-default-spawn-position` / `player-input`, per-dimension chunk decode and memory, an `:enter-portal` intent whose completion is an observed dimension change, a `:fortress` goal built on passive sightings plus an enclosed `:tunnel` intent with lava capping, a `:bridge` intent (sneak + place), and a sim nether fixture. It depends on the portal-cast issue for `:place` and a lit portal; it is the step the siblings reached only this month and both found a new wall right behind it.

## Why now / what the siblings learned

Both siblings entered the Nether naturally for the first time only recently: ruststeve `rust-race-002` on 2026-09-28 (`ruststeve-nether-loop-2026-09.md`: "entered the nether NATURALLY on Server B"), steve `steve-race-005` at ~90 min on 2026-10-09 (`steve-cycle7-first-race-nether.md`). Both then hit the same two walls, which this issue is designed around:

- **The world model broke on the dimension change.** ruststeve `bot/mod.rs:641-666`: "chunk keys are just (cx,cz), so overworld columns (min_y -64) kept answering nether lookups ... rust-nether-001 reported fortress brick at (4,-3,147) — RCON: nether_bricks at (4,61,147), exactly 64 higher", and "the parser ran off the end of the (shorter) nether chunk buffer → panic". The fix clears `columns`/`entities` and sets `(min_y, height)` to `(0, 256)` (`bot/mod.rs:658-664`) and does the same at login (`bot/mod.rs:902-906`). typecraft does it properly: `registry_data` entries for `minecraft:dimension_type` are skimmed for `height` / `min_y` (`src/lib/typecraft/bot/game.ts:53-81`), and the `respawn` `dimension` field is a **registry index** ("26.x sends the dimension as a REGISTRY INDEX (e.g. 3 = the_nether), not a name", `game.ts:119-126`); `chunkColumn.ts:65` derives `numSections = worldHeight >> 4`. typecraft also sends `player_loaded` after every respawn (`game.ts:176-182`: "until then the server can ignore block use").
- **Finding the fortress is solved; reaching it is not.** ruststeve `docs/nether-design.md` "Phase 2 harness summary": "find the fortress (loaded-chunk scan) | solved — every bot, every run, from 80–108 blocks, <2 min"; "reach it alive | open route: 9+ falls into the lava sea at one spot". Its `loaded_block_nearest` (`nether.rs:65-75`) scans loaded palettes with no line of sight, y 32..127 only ("picked fortress brick at (-180,16,240) — 15 blocks BELOW the sea surface"). The approach is **enclosed**: `nether.rs:141-157` tunnels toward the brick "dominant axis each step" and descends first when the brick is >3 below; `nether_tunnel_step` (`nether.rs:254-293`) caps lava touching the next 1x2 cells with cobble, fills a missing floor, digs, walks. Their race i6 note (`CHANGES.md:610`): "the next nether wall is the enclosed approach to a visible fortress". steve's `findFortress` is the thing not to copy: a 60 s sprint along X with a one-block footing check (`tasks/nether/main.ts:36-99`).
- **Arrival needs chunk truth, not a timer.** `nether-design.md` run 3: "the bot's client world had not streamed when the step loop started ... Arrival = wait for real chunk data, not a timer." Our `physics-ready?` already gates on `chunk-loaded?` (`game.clj:238-242`); it must survive the chunk reset.
- **Step selection must be dimension-aware.** `CHANGES.md:225`: a nether bot was "sent back to mine_iron in the nether"; steve's rows gate on `s.world.dimension` (`steps.ts:465-470`).
- **Blazes need `difficulty normal`.** `nether-run.sh:98-100` ("blazes need non-Peaceful"); `arena-run.sh` builds an overworld brick box with a blaze spawner and `summon`s. Fortress spawns come from `worldgen/structure/fortress.json` `spawn_overrides` (blaze weight 10, wither_skeleton 8, magma_cube 3). Our local server runs peaceful (`local-server.sh:14`), which is fine for this issue: reaching nether bricks needs no mobs, and peaceful removes ghasts, the "main killer" at bridge edges.

Vanilla facts confirmed from the 26.1.2 jar (`data/minecraft/dimension_type/*.json`): `the_nether` `min_y 0, height 256, logical_height 128, coordinate_scale 8.0, water_evaporates true`; `overworld` `-64 / 384`; `the_end` `0 / 256`. So the Nether column is **16 sections** (y 0..255), not 8; the 128 figure is the logical height (portals and beds). Fortress placement: `structure_set/nether_complexes.json` `random_spread spacing 27 separation 4` chunks, fortress weight 2 vs bastion 3. Registry ids: `:registry-data` 7 (configuration), `:respawn` 82, `:game-event` 38, `:set-default-spawn-position` 97, `:player-input` c2s 43, `:client-command` c2s 12 (`resources/clojurecraft/packets.edn`). Block states: `nether_bricks 9334`, `netherrack 6997`, `lava 102-117` (type `:liquid`, shared with water), `nether_portal 7017-7018`, `spawner 3888`, `obsidian 3369` (`blocks.edn`).

## Design

**World attributes (accreted, never redefined).** `:world/dimension` keyword (`:overworld` `:the_nether` `:the_end`), `:world/dimension-id` (the SpawnInfo varint), `:world/sea-level`, `:world/portal-cooldown`, `:stats/dimension-changes`, `:stats/deaths`. `:world/chunks` keeps its meaning (the current dimension's snapshot) and is emptied on a dimension change, exactly as the server restarts the stream; each column value carries `:chunk/min-y` and `:chunk/sections` so `block-at` / `section-index` / `find-blocks` read the column, not a global. Memory becomes dimension-keyed: new attribute `:memory/sightings {[dim x y z] {:block/state :block/seen-at}}`; `:world/sightings` stays as the superseded name (spec keeps it, `summary` counts both) per the accrete rule. `memory/remember-column`, `observe`, `remembered` keep their signatures and read `:world/dimension`. `watched?` grows from `log?` to a table: logs, `nether_bricks` / fence / stairs, `spawner`, `nether_portal`, `obsidian`, `lava` sources (ids by name, since `:liquid` covers water).

**`resources/clojurecraft/dimensions.edn`** generated by `datagen` from the jar's `data/minecraft/dimension_type/<name>.json` (the `--reports` tree has none: `data/reports/reports/minecraft/` holds only `components`): `{:overworld {:min-y -64 :height 384 :sections 24 :logical-height 384 :coordinate-scale 1.0} :the_nether {:min-y 0 :height 256 :sections 16 :logical-height 128 :coordinate-scale 8.0} :the_end {...}}`. Live path, later: `[:configuration :s2c :registry-data] [[:id :string] [:entries [:vec [[:key :string] [:nbt [:option :nbt]]]]]]` with a minimal NBT skimmer that returns only int fields `min_y` / `height`; the entry order is the numeric id SpawnInfo sends (typecraft: 3 = the_nether). Until then the id→name map is the table's row order.

**Packet specs** (`packet.clj`, additive; `[:option T]` is a new bool-prefixed type): `SpawnInfo` = `[[:dimension :varint] [:name :string] [:hashed-seed :i64] [:gamemode :u8] [:previous-gamemode :i8] [:debug? :bool] [:flat? :bool] [:death [:option [[:dimension :string] [:pos :position]]]] [:portal-cooldown :varint] [:sea-level :varint]]` (typecraft `shared-types.ts:2064-2091`); `[:play :s2c :respawn] (conj SpawnInfo [:copy-metadata :u8])` (`packet-defs.ts:1316-1317`); `[:play :s2c :login]` extended through `worldState` (hardcore, levels, max-players, view/sim distance, three bools, SpawnInfo, enforces-secure-chat; field order to verify against `packet-defs.ts:790-806`); `[:play :s2c :game-event] [[:reason :u8] [:param :f32]]` (13 = `level_chunks_load_start`, `packet-defs.ts:578-591`); `[:play :s2c :set-default-spawn-position] [[:pos :position] [:yaw :f32]]`; `[:play :c2s :player-input] [[:flags :u8]]` (sneak is bit 5 here; 775's `player-command` no longer carries sneak, `packet-defs.ts:2562` lists `leave_bed`/`start_sprinting`); `[:play :c2s :client-command] [[:action :varint]]` (0 = respawn after death).

**Reducer.** `on-packet [:play :respawn]`: if `dimension` differs from `:world/dimension` → assoc the new dimension, `:world/chunks {}`, `:world/entities {}`, `:world/blocks {}`, `:player/loaded? false`, bump `:stats/dimension-changes`, emit `:player-loaded`; same dimension → a death: bump `:stats/deaths`, emit `:client-command 0`, clear `:plan/intent`. `load-chunk` decodes with the row for `:world/dimension`. `plan/choose` filters goals by `:goal/dimension` so overworld goals never run in the Nether.

**Intents.** `:enter-portal {:intent/target portal-pos}`: walk to the column centre, hold within 0.4 of it looking into it; done when `:world/dimension` is `:the_nether` (the vanilla 80-tick stand; steve `enter.ts:45-64`); fail `:no-teleport` after 15 s. `:tunnel {:intent/dir [dx dz] :intent/steps n}`: one 1x2 step per cycle via existing `:dig` plus the portal issue's `:place`: cap lava in the 5 neighbours of the two ahead cells and their floor with cobblestone, fill a missing floor, dig, step; fail `:no-cobble` / `:blocked`. `:bridge {:intent/target [x y z]}`: sneak (`:control/sneak?` → physics clamps the edge and halves speed, `:player-input` flag sent while it changes), look down at the edge face, place under the feet, step. `:walk` gets a footing rule: refuse a step whose next feet cell is lava or whose floor is air over lava → fail `:no-footing`, so the planner picks `:tunnel`.

**Goal `:fortress`** (`:goal/dimension :the_nether`): done when a remembered `nether_bricks` is within 6 blocks of the feet. `next-intent`: nearest fortress sighting in this dimension with y ≥ 32 → `:tunnel` toward it on the dominant axis (descend via `:dig` first when it is >3 below, ruststeve `nether.rs:148-157`); none → `:tunnel` along ±X at the current y (ruststeve's "Idea A", y≈64 where corridors y≈48..80 meet terrain, sea at y 31), flip after 250 blocks, then ±Z. Sightings arrive passively from chunk load (view distance 6 → ±96 blocks), which is ruststeve's "Idea B" for free.

**Sim.** `sim/init` takes `:columns {[cx cz] bytes}` per dimension and `:sim/portal` cells; when the player stays inside a portal column 80 ticks it sends `respawn` (dimension 3, name `minecraft:the_nether`), a teleport, 16-section columns, `chunk-batch-finished`. `world/column-bytes` is parameterised by `{:min-y :sections}` (today `dotimes [si 24]`, `world.clj:28`). Fixture `nether-fragment`: netherrack floor y 60..63, a `nether_bricks` slab 24 blocks east at y 64, a lava single-section below y 32.

**Specs.** `:world/dimension`, `:memory/sightings` keys of 4 ints, `:goal/dimension`, intents above, `::spawn-info`; fdefs unchanged.

## Steps

1. `dimensions.edn` + datagen from the jar; `chunk/decode` takes a row, columns carry `:chunk/min-y`; tests decode a 16-section column. Verify: `clojure -M:test`, `chunk_test` has a nether case.
2. Specs for respawn/login/game-event/spawn-position/player-input/client-command with round-trip tests on captured bytes (record a login with `--record`). Verify: `clojure -M:replay` of an existing run gives the same `RESULT`.
3. Reducer: `:world/dimension`, chunk reset on change, death vs dimension-change branch, `player-loaded` ack. Verify: `game_test` folds a respawn and asserts the reset and the ack.
4. `:memory/sightings` keyed by dimension, wider `watched?`. Verify: overworld and nether sightings at the same `[x y z]` coexist.
5. `:enter-portal` in sim with the portal rule. Verify: sim e2e dimension flip.
6. `:tunnel`, `:walk` footing rule, `:bridge` with sneak physics. Verify: physics test (sneak never leaves a block edge), sim fixture with a lava gap crossed by `:tunnel`.
7. `:fortress` goal, `:goal/dimension` filter. Verify: sim e2e from the nether fixture to the brick slab.
8. Live: RCON `execute in minecraft:the_nether run tp` onto a netherrack pad 120 blocks west of `locate structure minecraft:fortress` (as `nether-run.sh:1-8`), kit iron pickaxe + 64 cobblestone, run `--until fortress`.

## Acceptance criteria

- Unit: `dimensions.edn` rows for the three dimensions; a 16-section column decodes and `block-at` reads y 0..255 correctly; a 24-section column still does.
- Unit: a `respawn` with a new dimension empties `:world/chunks`, sets `:world/dimension :the_nether`, emits `:player-loaded`; a same-dimension `respawn` counts a death and emits `:client-command`.
- Sim e2e: from a lit portal fixture the bot ends in `:the_nether` and `:plan/done?` for `:fortress` holds with nether bricks remembered within 6 blocks; the run is recorded and replays identically.
- Live (local server, peaceful): after an RCON tp into the Nether and a located fortress, `RESULT {:ok true}` and the judge `execute as <name> at @s if dimension minecraft:the_nether` passes plus `execute as <name> at @s if block ~ ~-1 ~ minecraft:nether_bricks` (or brick within 6 via `execute if blocks`), with 0 deaths in `:stats/deaths`.
- CI: a `gym.edn` row `{:gym/goal :fortress :gym/prereqs ["iron_pickaxe 1" "cobblestone 64"] :gym/landing :nether-pad :gym/truth ...}` (issue 03) runs 6 landings; pass rate reported with the Wilson line.
- No AI attribution; no attribute changes meaning; goals and intents are defmethods in new namespaces (`nether.clj`, `fortress.clj`).
