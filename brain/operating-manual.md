# How to use this brain

## The one rule
Read, do not dump. Traverse the graph; pull only the notes a question needs. A working set is [[_index]], one or two MOCs, and five to ten notes.

## The navigation path
1. Read [[_index]] and pick a pillar: `bot` (this code), `game` (vanilla 26.1.2 facts), `siblings` (what steve and ruststeve learned).
2. Open the pillar hub, then the area MOC; its one-line hooks say what each note answers.
3. Open the notes; follow `related` and `See also` only as far as the question requires.

## How to trust a note
- `status: verified` means someone opened the cited source at the pinned version and read it. `draft` means not yet; a draft from sibling research says so in its Limits.
- To orient, trust it. To act, open the `sourceRefs` and confirm; fine details drift first.
- If a note and the code disagree, the code wins. Fix the note in the same change.

## What lives here versus elsewhere
- Here: how the bot works, why it is shaped this way, what was tried and rejected, durable gotchas, vanilla facts the code relies on.
- Elsewhere: `docs/hickey.md` (the design essay), `docs/issues/` and the GitHub issues (the roadmap), `CLAUDE.md` (commands), code comments (the line you are on).
